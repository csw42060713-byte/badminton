# 🏸 배드민턴 분석 앱 (모바일 PWA)

구글 시트(`배드민턴 분석앱` · `출력결과`)로 만들던 앱을 **손가락에 바로 반응하는 모바일 앱**으로 옮긴 프로토타입입니다.

## 1. 바로 열어보기

```bash
# 이 폴더(badminton-app)에서
python3 -m http.server 8000
# 컴퓨터: http://localhost:8000
# 같은 와이파이의 휴대폰: http://<컴퓨터 IP>:8000
```

> `index.html`을 더블클릭해도 대부분 동작합니다. 다만 **홈 화면에 설치(PWA)** 하거나
> **오프라인 캐시**를 쓰려면 위처럼 주소로 열어야 합니다(https 또는 localhost 필요).

첫 실행에 환영 안내가 뜨고 **빈 상태**로 시작합니다(데모 인물·샘플 글 없음).
예전 버전을 설치했던 기기에 남아 있던 샘플 커뮤니티 글은 앱이 시작할 때 한 번 걸러 내고 저장소에서도 지웁니다.

### 시작화면과 계정 (v1.1)

앱을 처음 열면 하단 탭바 없이 **브랜드 시작화면**만 보입니다. 세 갈래 길 중 하나를 고르면 됩니다.

| 길 | 동작 |
| --- | --- |
| **Google로 계정하기** | Google Identity Services(GIS)로 실제 구글 계정(이메일·이름·사진) 로그인/자동 가입. OAuth Client ID가 없으면 안내 시트 + **데모 Google 계정으로 미리보기**로 이어집니다. |
| **이메일로 로그인 · 회원가입** | 이메일·비밀번호 폼. 브리지 주소가 저장돼 있으면 시트 계정(`login`/`register`), 없으면 이 기기에만 저장되는 체험 계정(비밀번호는 SHA-256 해시)으로 동작합니다. |
| **로그인 없이 둘러보기** | 이 기기에만 저장되는 체험 모드로 바로 입장. |

- **10초 온보딩**: 신규 가입자는 첫 로그인 직후 **닉네임 · 급수(자강·선수부·A~D조·초심) · 주력 종목 · 성별(선택) · 지역 · 클럽(선택)**을 한 화면에서 고르고 `시작하기`를 누르면 **일지 & AI**로 들어갑니다. 급수/종목이 비어 있는 기존 계정도 한 번만 묻습니다.
- **MY > 계정 카드**: 지금 상태(Google 연동 / 이메일 계정 / 체험 모드), 로그아웃. 개발자용 `고급 · Google Client ID` 입력란은 첫 화면을 단순하게 두려고 **MY > 데이터 연결 > 고급**으로 옮겼습니다.
- 계정별 데이터는 저장 키가 따로입니다(`bm_rows_v1::이메일`). 로그아웃해도 그 계정의 기록은 기기에 남고, 다시 로그인하면 이어집니다.

> **Google 로그인은 별도 설정 없이 바로 됩니다.** `js/auth.js`의 `DEFAULT_GOOGLE_CLIENT_ID`에 배포된 웹 클라이언트 ID가 들어 있어서입니다
> (OAuth 프로젝트 `badminton-app` / 클라이언트 `배드민턴 웹`, 승인된 JavaScript 원본 `https://csw42060713-byte.github.io`, 게시 상태 프로덕션).
> 다른 Google Cloud 프로젝트 것을 쓰려면 **MY > 데이터 연결 > 고급 · Google Client ID** 에 붙여넣으면 그 기기에서만 그 값이 우선합니다(지우면 기본값으로 복귀).

## 3. 하트 · 보상형 광고 (수익 구조)

하트는 **행(row)이 곧 원장**입니다. 캐시 숫자를 믿지 않고 `출석하트`·`광고하트`·`선물하트`·`내하트사용`·`꾸미기구매` 행을 세어 잔액을 계산합니다.
규칙은 `js/domain.js`의 `HEART_RULES` 와 `APPS_SCRIPT_BRIDGE.gs`의 `CONFIG` **두 곳에 같은 값**으로 있습니다(앱=화면·즉시 반응, 서버=최종 판정).

| 구분 | 항목 | 값 | 제한·중복 방지 |
| --- | --- | --- | --- |
| 적립 | 가입 기본 | +3 | 1회 |
| 적립 | 출석 체크 (`출석하트`) | +1 | **하루 1회** (서버가 오늘 행 존재 여부로 판정) |
| 적립 | 보상형 광고 (`광고하트`) | +1 | **하루 5회 · 30초 간격** (서버가 마지막 시청 시각과 오늘 횟수로 판정) |
| 적립 | 선물 받음 (`선물하트`) | +1 | 보낸 사람 1개 차감 |
| 적립 | 하트 합치기 (`하트합치기`) | +N | 기존 데이터 호환 |
| 사용 | 1:1 매칭 신청 (`매칭신청`+`내하트사용`) | −2 | 잔액 부족 시 `하트 충전하기`(출석·광고)로 바로 연결 |
| 사용 | 꾸미기 테마 (`꾸미기구매`) | −2 (라임·사쿠라) | 이미 산 테마는 재적용 무료 |
| 사용 | 하트 선물 (`선물하트`) | −1 | 받는 사람 +1 |

**광고 → 하트 흐름**

```
[광고 보고 받기] 버튼
  → (앱) window.BadmintonNative.showRewardedAd('heart_reward')   ← AdMob 등
  → 시청 완료: BadmintonNative 가 BM.app.onRewardAdResult(true, 'heart_reward') 호출
  → (웹/프로토타입) 3초 모의 광고 재생 후 같은 경로로 합류
  → store.actions.watchAd({verified:true})
  → 브리지: 오늘 횟수·30초 간격·세션 사용자 검사 → 시트에 광고하트 행 1개 추가
  → 원장·잔액·버튼(남은 횟수/쿨다운) 즉시 갱신
```

**파밍(어뷰징)을 막는 장치** — 화면 잠금은 편의일 뿐, 실제 판정은 서버에서 합니다.
1. 버튼 연타 잠금(1.2초) + 요청마다 `clientId` → 같은 요청은 한 번만 저장(6시간 캐시)
2. 서버가 **오늘 광고 횟수**를 세어 하루 5회 초과 거절 (`code: ad_limit`)
3. 서버가 **마지막 시청 시각**을 보고 30초 이내 재요청 거절 (`code: ad_cooldown`)
4. 보상 값(`좋아요`)은 **서버가 정함** — 앱이 100을 보내도 1로 저장
5. 작성자(`사용자ID`)는 **세션 값으로 강제** — 남의 계정으로 적립 불가
6. 광고 SDK 연동 시에는 `verified` 신호가 있을 때만 적립하도록 확장 가능

**확장 아이디어**(다음 단계): 하트 충전 인앱결제 패키지, 시즌 이벤트 보너스, 친구 초대 보상, 받은 하트 랭킹, 코치 피드백에 하트 걸기.

## 4. 매칭 검색 · 성별/급수 필터 (v1.2)

- **실시간 검색**: 매칭 탭 상단 검색창에 닉네임 · 지역 · 클럽 · 소개 · 급수 · 종목 낱말을 치면 한 글자마다 바로 걸러집니다. 지우기(×) 버튼 포함, 공백과 대소문자는 무시합니다.
- **필터 칩**: 급수(전체·자강·선수부·A조·B조·C조·D조·초심) · **성별(전체·남성·여성)** · 종목(전체·단식·복식·혼합복식) · 지역. 여러 조건을 동시에 좁힐 수 있고, `N명 찾음`과 `조건 초기화`가 함께 나옵니다.
- 성별은 `남성`·`여성`·`비공개` 세 값이며, 밝히지 않은 사람(`비공개`)은 성별 필터에서 빠집니다.
- 결과는 **궁합 점수 높은 순**으로 정렬됩니다.

## 5. 프로필 사진 꾸미기 (v1.2)

- **MY > 프로필 꾸미기** 또는 프로필 카드의 카메라 버튼에서 내 사진을 올릴 수 있습니다. 사진은 브라우저에서 **256×256 정사각형으로 잘라 JPEG로 압축**(필요하면 200/160px로 한 번 더 줄임)해 저장하므로 저장 공간과 시트 한 칸을 지킵니다.
- **프레임 6종**(기본 · 코트그린 · 골드 · 로열블루 · 사쿠라 · 네온), **배경 6종**(담백 · 민트 · 오션 · 선셋 · 그레이프 · 라임), **배지**(🏸 🔥 ⭐ 🥇 👑 🦋)와 이모지로 꾸밀 수 있습니다. 시트 안에서 미리 보며 고르고 `저장`을 누르면 적용됩니다.
- 꾸민 모습은 **MY · 1:1 매칭 카드/프로필 시트 · 커뮤니티 · 코치**에 같은 아바타 렌더러(`ui.js`의 `UI.avatar`)로 그려집니다.
- 저장 위치는 그대로 26칸 구조입니다: 프로필 행의 **꾸미기** 칸 JSON(`avatar`, `avatarPhoto`, `avatarFrame`, `avatarBg`, `avatarBadge`)과 매칭프로필 행 **소셜글** 칸 JSON(같은 키 + `gender`).

## 6. 급수 기반 1:1 매칭 규칙

- 급수는 **자강 · 선수부 · A조 · B조 · C조 · D조 · 초심** 7단계(강한 순). 지역·종목과 함께 필터로 쓰고, 궁합 점수는 급수 차이를 가장 크게 봅니다(같은 급수 +24, 한 단계 차이 +12, 그 외 +2).
- 예전 시트의 `실력` 값은 읽을 때 자동 변환됩니다: `초보용→초심`, `일반부→C조`, `상급→B조`, `선수부→선수부` (`normalizeGrade`).
- **요청 전 확인 단계**: 카드에는 급수 배지·주력 종목 칩·궁합만 보이고, 누르면 프로필 시트가 열립니다. 시트에서 **주력 종목(단식/복식/혼합복식)**·급수·지역·클럽·가능 시간·경력·소개를 확인한 뒤 `요청 보내기` 또는 `닫기`를 고릅니다. 프로필을 보지 않고는 신청할 수 없습니다.
- 받은 신청은 같은 시트에서 `수락하고 대화하기` / `거절`, 이미 매칭된 상대는 `채팅하기`로 바뀝니다.

## 6-1. 상단 채팅(DM) · 친구 추가 (v1.3)

- **상단바 오른쪽 채팅 아이콘**을 누르면 카톡·인스타처럼 **채팅 목록**이 열립니다. 아이콘에는 **안 읽은 메시지 + 받은 친구 요청** 수가 배지로 붙습니다.
- 목록 맨 위에 **받은 친구 요청**(수락/거절)이 뜨고, 그 아래에 **친구**·**1:1 매칭 성사 상대**와의 대화방이 아바타·닉네임·최근 메시지·시간·안 읽은 배지와 함께 보입니다. 아직 메시지가 없는 친구/매칭 상대도 눌러서 첫 대화를 시작할 수 있습니다.
- **대화방**은 위쪽에 뒤로가기 + 상대 아바타·닉네임·급수, 가운데에 말풍선(내 메시지 오른쪽 코트그린/라임, 상대 왼쪽 흰/회색 + 아바타 + 시각), 아래에 입력창·전송 버튼이 있습니다. 엔터 전송, 연타 중복 전송 방지, 방을 열면 읽음 처리됩니다.
- **친구 추가(친추)**: 커뮤니티 글쓴이나 매칭 프로필에서 `친구 추가` → 상대가 `수락`하면 친구가 됩니다. 프로필 버튼은 상태에 따라 `친구 추가` / `요청 보냄` / `수락·거절` / `친구 끊기`로 바뀝니다.
- 1:1 대화는 **친구이거나 1:1 매칭이 성사된 상대**와만 가능합니다(서버에서도 검사).
- 시트에는 `친구요청`·`친구수락`·`친구거절`·`친구삭제` 행으로 남고, 두 사람의 관계는 그 행들을 접어서 계산합니다(`domain.friendState` → `none`/`sent`/`received`/`friends`). 친구수락 행의 ID가 두 사람의 대화방 ID가 되어, 어느 기기에서 봐도 같은 방으로 묶입니다.

## 8. 실제 구글 시트에 연결하기

시트를 **공개하지 않고** Apps Script 웹 앱만 통로로 씁니다.

1. 시트 `배드민턴 분석앱` → **확장 프로그램 > Apps Script**
2. `APPS_SCRIPT_BRIDGE.gs` 내용을 전부 붙여넣기 → 저장
3. **프로젝트 설정 > 스크립트 속성**에 `SHEET_ID` 추가 (값 = 시트 주소의 `/d/` 와 `/edit` 사이 문자열).
   공개 저장소에 시트 ID가 올라가지 않도록 코드에는 넣지 않았습니다.
4. 맨 위 `CONFIG.SECRET` 을 **길고 임의의 문자열**로 바꾸기 (비밀번호·공개ID 해시에 섞입니다)
5. 편집기에서 `setup()` 실행 → 권한 승인 (헤더 확인, ID·비밀번호 열을 '텍스트' 서식으로 고정)
6. **배포 > 새 배포 > 웹 앱**
   - 실행 사용자: **나**
   - 액세스 권한: **모든 사용자**
   - 배포 후 나온 `https://script.google.com/macros/s/…/exec` 주소 복사
7. 앱 **MY > 시트 연결**에 주소·이메일·비밀번호·닉네임 입력 → 연결
   (그 뒤로는 **시작화면의 이메일 로그인**이 같은 시트 계정으로 동작합니다: `login` / `register`)

> 처음 입력하는 이메일은 자동으로 가입됩니다(프로필 행 생성 + 비밀번호 해시 저장).
> 이미 쓰던 이메일이면 그 계정으로 로그인합니다.
> 코드를 고친 뒤에는 **배포 관리 > 수정 > 새 버전**으로 다시 배포해야 반영됩니다.

## 10. AI는 어떻게 판단하나

`js/ai.js` — 정답이 정해진 규칙 기반입니다(같은 입력 → 항상 같은 결과, 네트워크 불필요).

- **점수(0~100)**: 컨디션·강도 균형, 운동 시간, 승패, 통증 개수, 코어/유산소 포함, 연속 훈련일을 가감
- **진단 5줄**: 최근 5경기 승률 / 컨디션-강도 차이 / 운동 시간 / 반복 통증(4주 2회 이상) / 자주 나온 약점
- **추천드릴 3개**: 약점 기술(드라이브·헤어핀·드롭·클리어·스매시·풋워크·서브·리시브)별 라이브러리에서 실력에 맞는 세트 수로 선택
- **맞춤처방**: 부위별(목·어깨·허리·팔꿈치·무릎·손목·아킬레스건·발목) 회복/스트레칭 + 마음가짐 3줄
- **경고**: 통증 + 높은 강도, 반복 통증(2주 이상이면 진료 권장), 6일 연속 훈련, 주간 부하 급증
- **경기 흐름**: 그날 남긴 경기 점수만으로 점수제(21·25점제)·평균 점수차·접전(3점차 이내)·끝까지 간 경기·큰 점수차 패배·"첫 경기 대비 마지막 경기 점수차"를 읽고 실전 문구를 만듭니다(중간 흐름은 기록이 없으므로 추측하지 않음)
- **주간 부하 점검**: 운동 시간 × 주관적 강도(세션 RPE)로 최근 7일 부하를 직전 4주 주당 평균과 비교(0.8~1.3 참고 구간, 1.5 이상 급증). 4주 평균을 낼 기록이 없으면 이 항목은 나오지 않습니다

## 12. 안전해진 점

- **비밀번호는 앱에 오지 않습니다.** 브리지가 SHA-256(120회 반복 + salt) 해시만 시트에 저장하고, 응답에서 `비밀번호` 칸을 항상 비웁니다.
- **이메일도 앱에 오지 않습니다.** 사용자 키는 `u + 해시15자` 공개 ID로 바뀌어 내려가고, 브리지가 요청을 받을 때 원래 키로 되돌립니다.
- **작성자는 서버가 정합니다.** 앱이 보낸 `사용자ID`는 무시하고 로그인 세션 값으로 덮어써서, 남의 이름으로 글을 쓰는 위조가 불가능합니다.
- **수정 권한 제한**: 내 행(또는 관리자)만, 정해진 칸만 바꿀 수 있습니다. 멘토·코치 신청의 **승인/거절(승패·소셜글)은 관리자만** 가능합니다.
- **시트는 비공개 유지**: 시트 공유 설정을 '비공개'로 두고 웹 앱만 배포하면 됩니다.
- **ID 깨짐 방지**: `1.79229E+15` 처럼 과학적 표기로 깨지던 ID를 `setup()`이 텍스트 서식으로 고정합니다. (깨진 행은 `깨진 ID 찾기` 메뉴로 확인)

## 13. 기존 데이터 정리 (한 번만)

1. `setup()` 실행 → 헤더·서식 정리
2. 앱에서 **그동안 쓰던 이메일 + 지금 쓰는 비밀번호**로 로그인
   → 비밀번호 칸이 평문이면 **그 순간 해시로 자동 교체**됩니다(다음 로그인은 해시로 검사).
3. `깨진 ID 찾기`로 `1.79229E+15` 형태가 있는지 확인 → 있으면 해당 행은 ID를 새로 부여하거나 그대로 두어도 앱은 읽습니다.
4. 중복 저장된 기록(같은 날 같은 내용이 여러 행)은 시트에서 직접 지우면 됩니다. 앱은 지워진 행을 즉시 반영합니다.

## 15-16. v1.17.0 검정 배경 오류 수정 · 전체 디자인 폴리싱 (2026-11-20)

### 1) 흰 배경인데 검정이 비치던 오류 — 원인과 수정

원인은 세 곳이었습니다.

1. **`<html>`에 검정 배경이 박혀 있었습니다.** `index.html`이 `<html lang="ko" data-theme="th_night" style="background:#080b0a">`로 시작했습니다. 인라인 스타일은 어떤 CSS보다 세기 때문에, 밝은 테마(`th_def`·`th_sakura`)를 골라도 **html의 배경은 영원히 검정**이었습니다. body는 최대 460px라 화면 양옆·아래, 스크롤바 자리, 당겨서 새로고침하는 바깥 영역에서 그 검정이 그대로 보였습니다(390px 화면의 오른쪽·아래 검정 띠 = 세로·가로 스크롤바가 칠해진 html 배경).
2. **`<meta name="theme-color" content="#080b0a">`가 고정**이라 안드로이드 크롬 주소창·작업 전환기, 설치형 앱의 상태바가 밝은 테마에서도 검정이었습니다.
3. **`:root { color-scheme: dark }` + `<meta name="color-scheme" content="dark light">`** 때문에 스크롤바·날짜 입력칸 같은 브라우저 부품이 처음엔 어두운 색으로 잡혔고, `data-theme`는 앱 상태가 로드된 뒤(`paintChrome`)에야 붙어서 **첫 화면에서 어두운 껍데기가 한 번 번쩍였습니다**.

수정:

- `html`을 `data-theme="th_def"`(기본 코트)로 두고 인라인 검정 배경을 지웠습니다. 배경은 이제 `html { background-color: var(--bg) }`로 **테마 변수만** 따라갑니다.
- `<head>` 맨 앞에 **첫 페인트 전 테마 스크립트**를 넣었습니다. `localStorage`의 `bm_cache_v1`에서 마지막 테마를 읽어 `data-theme`와 `theme-color`를 CSS·첫 그림 전에 칠합니다(읽기 실패 시 `th_def`).
- `app.js`의 `paintChrome`이 테마를 바꿀 때마다 `meta[name="theme-color"]`도 함께 바꿉니다(`THEME_CHROME`). 값은 CSS의 `--bg`와 같습니다 — 테스트가 네 테마 모두에서 두 값을 대조합니다.
- `color-scheme`은 `light dark`(밝은 우선)로 바꾸고 테마별로 `color-scheme: light/dark`가 덮습니다. 날짜 입력칸·스크롤바도 테마를 따라갑니다.
- **설치형 앱의 실행 화면**도 검정이었습니다. `manifest.json`·`manifest.webmanifest`의 `background_color`·`theme_color`가 `#080b0a`였는데, 이제 밝은 기본 바탕 `#f6f8f6`입니다(첫 화면이 하얗게 뜨고, 앱 안에서는 테마에 맞춰 다시 칠해집니다).
- `html, body { overflow-x: clip }`과 `html { scrollbar-color: … }`로 가로 스크롤 띠와 검정 스크롤바를 없앴습니다.
- 다크 테마(`th_night`·`th_court`)에서도 같은 규칙이 반대로 동작하는지 확인했습니다(html 배경 = `#080b0a`/`#06170f`).

- **칸 매핑**: `ID→id`, `유형→type`, `작성일시→created_at`, `날짜→date`, `닉네임→nick`, `실력→level`, `주력종목→discipline`, `훈련계획→plan(jsonb)`, `컨디션→cond`, `훈련강도→intensity`, `운동시간(분)→minutes`, `완료훈련→done`, `게임점수→score`, `승패→win`, `아픈부위→pain`, `맞춤처방→prescription(jsonb)`, `약점기술→weakness`, `추천드릴→drills(jsonb)`, `소셜글→note / payload(jsonb)`, `좋아요→likes`, `사용자ID→user_key`, `대상→target`, `팀→team`, `자기소개→bio`, `꾸미기→theme(jsonb)`. `비밀번호` 칸은 **DB에 두지 않습니다**(앱 로그인은 그대로 시작화면 `auth.js`).
- **시각**: DB는 UTC `timestamptz`, 앱은 `YYYY-MM-DD HH:mm:ss` 문자열을 비교·정렬하므로 읽을 때 기기 시간대로 바꿔 넘기고, 쓸 때는 UTC ISO로 보냅니다(왕복해도 같은 값).
- **RLS 한계와 대응**: 현재 정책은 `anon` = SELECT/INSERT만, UPDATE/DELETE는 `authenticated` 본인만입니다. 그래서 anon 상태의 수정·삭제는 **덧붙이는 기록 행**(`수정` = `payload.cells`, `삭제` = `target`)으로 남기고, 읽을 때 원래 행에 겹쳐 읽고 가립니다. 겹치기는 **같은 `user_key`의 행에만** 적용해 남의 기록을 건드릴 수 없습니다. 나중에 Supabase Auth를 붙이면 1단계에서 시도한 진짜 `PATCH`/`DELETE`가 성공해 기록 행이 쌓이지 않습니다(코드는 그대로).
- **공개 키만**: 앱에는 `sb_publishable_…`(없으면 예전 `anon` JWT)만 들어가고, `service_role`·DB 비밀번호는 넣지 않습니다(테스트가 JWT 역할까지 확인).

### 2) 실시간 채팅·요청 (1초)

- `postgres_changes`(INSERT/UPDATE/DELETE, `public.app_records`)를 WebSocket으로 구독합니다. join → 하트비트 25초 → 끊기면 1초부터 최대 15초까지 지수 백오프로 **스스로 다시 붙습니다**.

## 15-26. v1.26.0 Supabase Auth 이메일 가입·계정 완전 독립 (2026-11-20)

### 2) `js/auth.js` — Supabase Auth 직행

| 기능 | 경로 |
|---|---|
| 회원가입 | `POST /auth/v1/signup` (닉네임은 `data.nick`) |
| 로그인 | `POST /auth/v1/token?grant_type=password` |
| 자동 갱신 | `POST /auth/v1/token?grant_type=refresh_token` — 만료 60초 전에 미리, 회전된 `refresh_token` 저장 |
| 로그아웃 | `POST /auth/v1/logout` + 기기 토큰 삭제 |
| 비밀번호 변경 | `PUT /auth/v1/user` (6자 미만은 서버에 보내지 않음) |
| 비밀번호 재설정 | `POST /auth/v1/recover` → 메일 링크(`#access_token=…&type=recovery`)로 돌아오면 새 비밀번호 시트 |
| 회원 탈퇴 | `POST /rest/v1/rpc/delete_my_account` |

- 로그인 직후 `app_users`에 `user_key`·`auth_uid`를 upsert해 RLS의 "본인 행"이 열립니다(`ensureAccount`).
- 실패 이유를 사용자 말로 바꿉니다: `invalid_credentials` → "이메일이나 비밀번호가 맞지 않아요", `user_already_exists` → "이미 가입된 이메일이에요" 등.
